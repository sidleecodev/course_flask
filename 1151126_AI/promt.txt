# Flask RESTful API 改造 — 相容 json-server

請依據我提供的 Flask 程式碼，將目前的產品管理 API 改造成符合 json-server 基本 CRUD 路由規則與資料回傳格式的 RESTful API，讓原本的前端 ERP 產品管理系統可以串接 Flask 後端。

## 一、資料結構

產品資料必須包含以下欄位：

| 欄位 | 資料型態 | 說明 |
|---|---|---|
| id | String | 系統自動產生的唯一識別碼 |
| name | String | 產品名稱 |
| category | String | 產品分類 |
| price | Number | 產品價格 |
| num | Integer | 庫存數量 |
| remark | String | 產品備註 |

使用 Python List 搭配 Dictionary 作為模擬資料庫，並建立至少 5 筆初始產品資料。

## 二、API 路由規格

依據 json-server 的 Array Resources 路由規則，實作以下 API：

| Method | Route | 功能 |
|---|---|---|
| GET | /product | 讀取全部產品 |
| GET | /product/:id | 讀取指定產品 |
| POST | /product | 新增產品 |
| PUT | /product/:id | 完整更新產品 |
| PATCH | /product/:id | 部分更新產品 |
| DELETE | /product/:id | 刪除指定產品 |

## 三、API 開發需求

1. ID 使用 UUID 自動產生，並採用字串格式。
2. GET 全部產品時，直接回傳 JSON Array。
3. GET 單筆、新增、更新及刪除產品成功時，直接回傳 JSON Object。
4. 不額外包裝 message、products、newdata 等欄位。
5. PUT 必須提供完整的可編輯欄位，PATCH 僅更新前端傳入的指定欄位。
6. 不允許前端修改產品 ID。
7. 加入 CORS 跨來源存取功能。
8. 伺服器使用 Port 8080，Host 設定為 0.0.0.0。

## 四、資料驗證與錯誤處理

1. 驗證前端傳入的 JSON 資料格式。
2. 產品名稱與分類不得為空白。
3. 產品價格必須為非負數，庫存數量必須為非負整數。
4. 產品名稱不得重複。
5. 找不到指定產品時，回傳適當的錯誤訊息。
6. 依據操作結果回傳正確的 HTTP Status Code（200、201、400、404、409）。

## 五、程式撰寫規範

1. 維持原本 Flask 程式碼的撰寫風格與架構。
2. 使用基礎 Python 語法，例如 for、if、List、Dictionary 及 Function。
3. 將重複使用的資料搜尋與驗證邏輯封裝成 Function。
4. 不使用資料庫、ORM、Blueprint 或過於進階的程式設計架構。
5. 加入適當的繁體中文註解，方便初學者閱讀與理解。
6. 程式碼必須完整排版，提供可直接複製至 VS Code 執行的完整 Python 程式碼。
7. 提供各 API 的測試網址、Request Body 與 Response 範例。

## 六、最終目標

在不修改原本前端 CRUD 核心邏輯的前提下，以 Flask 取代 json-server，並作為後續串接 MySQL 資料庫的基礎。
